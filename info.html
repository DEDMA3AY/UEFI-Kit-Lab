UEFI Kit Labv2.82 · X64 · UEFI

RU

Универсальный диагностический комплекс для UEFI-платформ — работает напрямую из загрузочной флешки, без установки и ОС.

Анализ памяти: чтение SPD всех планок (DDR3/DDR4/DDR5) по SMBus с автоопределением типа, производителя, объёма и частоты; полный физический тест ОЗУ с выявлением нестабильных ячеек.
Диагностика на уровне ячеек: 25 тестов (функциональные, деградационные, Rowhammer/TRR, термические), восстановление карты банков/строк/рангов/каналов прямо на железе (методика DRAMA), декод физического адреса в канал/планку/ранг/банк в реальном времени, анализ залипших битов, карта ошибок по микросхемам, экспорт BadRAM.
Сохранение дампа SPD вставленной в плату памяти: каждая планка выгружается отдельным файлом .bin — SPD любой памяти (DIMM/SO-DIMM) можно сохранить и открыть в Thaiphoon Burner, HWiNFO или hex-просмотрщике.
Полный контроль BIOS: дамп и восстановление микросхемы SPI BIOS с разблокировкой защиты записи, а также дамп видеокарты (vBIOS / Option ROM).
Мониторинг платформы: живой профиль XMP/EXPO, применённые тайминги IMC (Intel MCHBAR / AMD Zen SMN), счётчики повторов IMC, мощность RAPL, температура, MCA/ECC и перезапуски. Сводка последнего прогона хранится в NVRAM и показывается при следующем старте (ошибки/температура/пропускная способность относительно прошлого раза).
Для сервиса и энтузиастов: диагностика неисправных модулей, резервное копирование прошивок перед модификацией, анализ совместимости памяти на конкретной плате — всё в одном месте, с понятным меню и подробными отчётами на самой флешке.

EN

Universal diagnostic suite for UEFI platforms — runs directly from a bootable USB stick, no installation, no OS.

Memory analysis: reads SPD of all installed modules (DDR3/DDR4/DDR5) over SMBus with automatic type, vendor, size and speed detection; full physical RAM test that uncovers unstable cells.
Cell-level diagnostics: 25 tests (functional, degradation, Rowhammer/TRR, thermal), on-board recovery of the bank/row/rank/channel address map (DRAMA method), real-time decoding of physical addresses into channel/DIMM/rank/bank, stuck-bit analysis, per-chip error maps, BadRAM export.
SPD dump of installed memory: each module is exported as a separate .bin file — the SPD of any memory (DIMM/SO-DIMM) can be saved and opened in Thaiphoon Burner, HWiNFO or a hex viewer.
Full BIOS control: dump and restore of the SPI BIOS chip with write-protection unlock, plus GPU vBIOS (Option ROM) dump.
Platform monitoring: live XMP/EXPO profile, applied IMC timings (Intel MCHBAR / AMD Zen SMN), IMC retry counters, RAPL power, temperature, MCA/ECC and restarts. A summary of the last run is stored in NVRAM and shown on the next start (errors/temperature/bandwidth relative to the previous run).
For service and enthusiasts: faulty module diagnostics, firmware backup before modification, memory compatibility analysis on a specific board — all in one place, with a clear menu and detailed reports on the stick itself.

Как записать дистрибутив на флешку

RU
  1. Скачай и запусти Rufus — https://rufus.ie.
    Программа бесплатная, портативная, установки не требует.
  2. Вставь флешку (минимум 8 МБ, лучше 256 МБ и больше — подойдёт любая).
    Внимание: всё содержимое флешки будет стёрто!
  3. В Rufus выбери образ uefi-kit-lab.iso из папки dist.
    Кнопка «ВЫБРАТЬ» справа от поля «Загрузочный носитель». Записывать нужно именно ISO, а не efiboot.img или BOOTX64.EFI.
  4. Оставь настройки по умолчанию: «ISO image», схема разметки GPT, целевая система UEFI (не CSM).
    Rufus сам подхватит эти параметры из образа, обычно менять ничего не нужно.
  5. Нажми «СТАРТ» и подтверди предупреждения.
    После окончания записи Rufus покажет «Готово».
  6. Извлеки флешку, вставь её в целевую машину и загрузись с неё в режиме UEFI (Boot Menu: F12 / F9 / F11 / F8 — зависит от вендора).
Внимание! Функции «Restore SPI BIOS» и «Unlock» перезаписывают микросхему BIOS целевой платы. Бракованный или неполный дамп при восстановлении может повредить систему — работай только с заведомо рабочим образом, снятым на этой же плате.
EN

English — writing the distribution to a USB stick

  1. Download and run Rufus — https://rufus.ie.
    Free, portable, no installation required.
  2. Insert the USB stick (8 MB minimum, 256 MB or more recommended — any stick will do).
    Warning: all data on the stick will be erased!
  3. In Rufus select the image uefi-kit-lab.iso from the dist folder.
    Use the "SELECT" button next to "Boot selection". Write the ISO itself, not efiboot.img or BOOTX64.EFI.
  4. Keep the defaults: "ISO image", partition scheme GPT, target system UEFI (non CSM).
    Rufus picks these up from the image automatically; normally nothing needs changing.
  5. Press "START" and confirm the warnings.
    Rufus reports "Ready" when the write completes.
  6. Eject the stick, insert it into the target machine and boot from it in UEFI mode (Boot Menu: F12 / F9 / F11 / F8 — vendor dependent).
Warning! The "Restore SPI BIOS" and "Unlock" functions overwrite the target board's BIOS chip. A bad or incomplete dump used for restore can brick the system — only work with a known-good image taken from that same board.

Что умеет программа

RU
Текущая ревизия: v2.82
  • <1> Test Memory — тест физической оперативной памяти.
    25 тестов (см. раздел ниже): функциональные 1–13 (включая March-C-, Rowhammer, Bit-Fade), термические/нагрузочные 14–20 (AVX2, VRM, пропускная способность), специализированные 21–24 (TRR-safe Rowhammer, retention sweep, CFst, March SS). Интерактивный экран теста, выбор набора (все / один), конфигурация (количество проходов, SMP, остановка по ошибке, обход кэша, диапазон адресов, режим Marathon), подсветка ошибок, F1 — дамп экрана в файл.
  • <2> Dump SPD — чтение SPD всех планок памяти.
    SPD DDR3 (256 байт), DDR4 (512 байт) и DDR5 (1024 байта) читаются напрямую через SMBus, по адресам 0x50–0x57. Автоопределение типа памяти по байту 0x12. Плюс человекочитаемый отчёт из SMBIOS Type 17: производитель, part number, серийный номер, объём, частота. Файлы именуются автоматически: <производитель>_DDR4_<тип>_<объём>GB_<скорость>_<part>.bin. Проверка контрольной суммы SPD (CRC-16 для DDR4/DDR5), отбраковка недописанного EEPROM, декод чипов DDR3 по сырому дампу.
  • <3> Dump SPI BIOS — дамп микросхемы BIOS флешки на загрузочный USB.
    Чтение через контроллер SPI: Intel PCH (HWSEQ/MMIO), AMD FCH (FIFO) и AMD SPI100 (Zen+). Автоопределение метода доступа и размера флешки, прогресс 0–100%, имя файла формируется из информации о плате.
  • <4> Restore SPI BIOS — разблокировка и восстановление BIOS из дампа.
    Выбор файла-дампа прямо с флешки, попытка снятия аппаратной блокировки записи (Intel FLOCKDN / AMD protection registers), секторное стирание и запись, детальный лог spi_restore_log.txt.
  • <5> Dump GPU vBIOS — дамп опцион-рома видеокарты на USB.
    Поиск видеокарт через перечисление шины PCI (EFI_PCI_IO_PROTOCOL с фолбэком на MCFG), чтение Option ROM, имя файла по VID/DID — например vbios_B1_D0_10DE_0F00.bin.
  • <6> Exit — выход в UEFI shell.
EN

English — Что умеет программа / features

  • <1> Test Memory — physical RAM testing.
    25 tests (see the section below): functional 1-13 (including March-C-, Rowhammer, Bit-Fade), thermal/load 14-20 (AVX2, VRM, bandwidth), specialized 21-24 (TRR-safe Rowhammer, retention sweep, CFst, March SS). Interactive test screen, run set selection (all / single), configuration (pass count, SMP, stop-on-error, cache bypass, address range, Marathon mode), error highlighting, F1 — screen dump to file.
  • <2> Dump SPD — read the SPD of all memory modules.
    DDR3 (256 bytes), DDR4 (512 bytes) and DDR5 (1024 bytes) SPD is read directly over SMBus at addresses 0x50-0x57. Automatic memory type detection via byte 0x12. Plus a human-readable report from SMBIOS Type 17: vendor, part number, serial number, size, speed. Files are named automatically: <vendor>_DDR4_<type>_<size>GB_<speed>_<part>.bin. SPD checksum verification (CRC-16 for DDR4/DDR5), rejection of half-written EEPROMs, DDR3 chip decoding from the raw dump.
  • <3> Dump SPI BIOS — dump the BIOS flash chip to the boot USB.
    Reads via the SPI controller: Intel PCH (HWSEQ/MMIO), AMD FCH (FIFO) and AMD SPI100 (Zen+). Automatic access-method and flash-size detection, 0-100% progress, file name built from board information.
  • <4> Restore SPI BIOS — unlock and restore the BIOS from a dump.
    Dump file selection right on the stick, attempt to remove hardware write protection (Intel FLOCKDN / AMD protection registers), sector erase and write, detailed log spi_restore_log.txt.
  • <5> Dump GPU vBIOS — dump the GPU option ROM to USB.
    Video cards are found by PCI bus enumeration (EFI_PCI_IO_PROTOCOL with an MCFG fallback), the Option ROM is read, the file name uses VID/DID — e.g. vbios_B1_D0_10DE_0F00.bin.
  • <6> Exit — return to the UEFI shell.

Тесты памяти — что именно делает каждый

RU

Меню «Test Memory» предлагает 25 тестов + «Run All Tests». Тесты 0–13 соответствуют нумерации MemTest86+ (T0–T11 и далее), 14–24 добавлены нами. Номера — это номера пунктов в меню выбора теста, а не внутренние ID.

Test 0 — SPD / SMBus Integrity [read EEPROM]

Проверка самих SPD-EEPROM по шине SMBus: контрольные суммы JEDEC + 128 полных пере-чтений каждого занятого EEPROM и сравнение образов. Ловит нестабильный SMBus / плохой контакт / сбоящую микросхему SPD. Одноразовый (не входит в Run All).

Test 1 — Address Walk Ones [no cache]

Записывает «шагающую единицу» на каждую линию адреса, принудительный сброс кэша WBINVD между проходами (каждое чтение идёт в DRAM). Ловит дефекты декодера адреса: слипшиеся/оборванные линии адреса, неправильные переходы между строками. Аналог MemTest86+ T0.

Test 2 — Address-as-Data [own address]

Записывает в каждую ячейку её собственный адрес (и инверсии), затем проверяет. Находит ошибки декодера: две ячейки, отображающиеся на один физический адрес, или ячейки, которые не пишутся вовсе. Аналог MemTest86+ T1/T2.

Test 3 — Bus stress [turnaround]

Интенсивные переходы чтение→запись→чтение с переключением всех битов данных в каждом слове. Нагружает шину данных и тайминги поворота (turnaround), ловит нестабильность шины и слабые сигналы данных. Аналог MemTest86+ T3.

Test 4 — Moving Inversions [1s & 0s + random]

Классические «плавающие инверсии»: заполнение паттерном 1s/0s с последующей инверсией побитно + случайные паттерны. Проверяет каждую ячейку на переход 0→1 и 1→0 и на соседские влияния. Аналог MemTest86+ T4/T5.

Test 5 — Moving Inversions 8-bit [pattern]

Шагающие единицы и нули в 8-битном представлении: паттерн вращается по каждому байту и проходится по всем 256 комбинациям (8 бит). Ловит отказы, зависящие от соседних битов в одном байте. Аналог MemTest86+ T6.

Test 6 — Modulo-20 [anti-cache]

Паттерн с шагом 20 адресов, специально подобран так, чтобы его нельзя было «замаскировать» кэшем (обход кэш-ассоциативности). Пишет и проверяет с этого шага. Аналог MemTest86+ T7.

Test 7 — Block move [64 moves]

Блочное перемещение 64 блоков памяти друг в друга и обратно. Нагружает шину памяти массовыми копированиями, ловит ошибки при интенсивной многоканальной работе и сбои строк/столбцов под нагрузкой. Аналог MemTest86+ T8. Верификация корректно прерывается при остановке теста — фантомные ошибки исключены (v2.82).

Test 8 — Moving Inversions 32/64 [shift]

Паттерн, который сдвигается на 1 бит для каждого адреса, с 64 различными смещениями. Покрывает все комбинации битовых сдвигов в 32/64-битных словах. Аналог MemTest86+ T9.

Test 9 — Bit-Fade / retention [direct]

Заполняет всю память паттерном, ждёт 30 секунд (пауза удержания) и перечитывает. Находит ячейки, теряющие заряд — деградационные (retention) отказы, которые другие тесты не видят, т.к. те проверяют сразу после записи. Аналог MemTest86+ T10.

Test 10 — Rowhammer [Blacksmith-style]

Упрощённый Blacksmith-подход: интенсивно «бьёт» (hammer) строки-агрессоры, затем проверяет соседние строки-жертвы. Ловит утечку заряда между физически соседними строками при частой активации — классический Rowhammer-отказ. Аналог MemTest86+ v7 Test 11.

Test 11 — March-C- multi-pattern [direct]

6-фазный маршевый тест March-C- с тремя паттернами на физической памяти (без вмешательства кэша). Покрывает залипшие биты, переходные отказы, coupling-отказы между соседними ячейками. Один из самых сильных функциональных тестов.

Test 12 — Checkerboard / Adjacent-Cell [direct]

Шахматное заполнение (чередующиеся 0/1) + фаза «бабочки» (flip соседних ячеек). Проверяет coupling-влияние соседних ячеек друг на друга и на шину данных.

Test 13 — Walking Ones/Zeros [exhaustive]

Полный исчерпывающий тест: единица «проходит» по каждому биту всех слов, затем инверсия. Очень медленный, но максимально полный по покрытию отдельных битов. Аналог MemTest86+ T13/Walking.

Test 14 — Cache Evict Storm [CLFLUSH]

Каждая строка кэша принудительно вытесняется командой CLFLUSH перед чтением — каждое чтение идёт физически в DRAM. Нагружает контроллер памяти и VRM большим потоком чтений без «маскировки» кэшем.

Test 15 — VRM Square-Wave [AVX2]

Переключение нагрузки на VRM прямоугольной волной: 10 Гц циклов «взрыв AVX2 FMA» ↔ «простой». Создаёт резкие скачки тока, ловит нестабильность питания памяти, просадки напряжения и связанные с ними сбои.

Test 16 — L3 Stress [L3 resident]

Read-modify-write в наборе размером ~1 МБ, умещающемся в L3. Замкнутый цикл по одним и тем же строкам — нагружает конкретные банки и строки повторно, ловит скрытые retention/coupling отказы в «горячих» строках.

Test 17 — Thermal Soak [3 min, AVX2]

3 минуты непрерывной AVX2 FMA-нагрузки + записей на всех ядрах. Разогревает память и IMC до максимальной мощности, ловит температурно-зависимые отказы (появляются только на горячей памяти). Сопровождается контролем температуры.

Test 18 — BW Soak [5 min, AVX2]

5 минут потоковой записи (non-temporal stores, vmovntdq — без загрязнения кэша) с последующей проверкой. Держит контроллер памяти на максимальной пропускной способности, ловит отказы под полной нагрузкой шины/каналов.

Test 19 — Stride-sweep BW [probe]

Замер пропускной способности чтения при шагах 64B / 1KB / 4KB / 64KB. Сканирует ассоциативность кэша и деления каналов/банков — диагностика производительности, а не только ошибок: показывает, попадает ли память в паспортные характеристики.

Test 20 — Vector PRSG [AVX2]

Псевдослучайный поток 4×64-бит (xorshift) на AVX2: заполнение + проверка вперёд/назад. Высокоэнтропийные паттерны покрывают межбитовые зависимости, которые «правильные» паттерны пропускают.

Test 21 — Rowhammer [TRR-safe]

TRRespass-стиль: 8 основных строк-агрессоров с простым шагом + ротация, для DDR5 двойные активации. Обходит защиту TRR (Target Row Refresh) — находит уязвимые строки, которые «обычный» Rowhammer 10 не видит из-за рефреша-защиты.

Test 22 — Bit-Fade Sweep [retention]

Градуированная деградационная развёртка: паузы 5/30/120 с (сплошная единица); при обнаружении утечки — эскалация до 5/15/30/60/120 с с двумя паттернами. Выдаёт вердикт CRITICAL/WARNING/OK по первому сбою и стабильным адресам.

Test 23 — CFst [state coupling]

Записывает состояние в строку-агрессор того же банка, затем читает строку-жертву без сброса. Находит coupling-отказы, где состояние агрессора влияет на чтение соседней строки (state-coupling fault).

Test 24 — March SS [22-phase]

22-фазный маршевый тест: полное покрытие state-coupling (CFst) + переходных отказов (TF). Самый полный маршевый алгоритм из используемых.

Run All Tests

Запускает функциональные тесты 1–13 дважды, затем термические/нагрузочные 14–20 четырежды (обозначение x2/x4 в прогрессе). Останавливается по ESC. Результаты сводятся в таблицу со скоростью прохождения, пропускной способностью и причиной пропуска (например, нет AVX2 / нет CLFLUSH / изолированный слот).
EN

English — what each test does

The "Test Memory" menu offers 25 tests + "Run All Tests". Tests 0-13 follow the MemTest86+ numbering (T0-T11 and on), 14-24 are ours. The numbers are the single-test menu positions, not internal IDs.

Test 0 — SPD / SMBus Integrity [read EEPROM]

Checks the SPD EEPROMs themselves over SMBus: JEDEC checksums + 128 full re-reads of each populated EEPROM with image comparison. Catches an unstable SMBus / poor contact / a failing SPD chip. One-shot (not part of Run All).

Test 1 — Address Walk Ones [no cache]

Writes a walking one across every address line with a forced WBINVD cache drop between passes (every read goes to DRAM). Catches address-decoder defects: shorted/open address lines, wrong row transitions. Analogue of MemTest86+ T0.

Test 2 — Address-as-Data [own address]

Writes each cell's own address (and its inversions), then verifies. Finds decoder errors: two cells mapping to one physical address, or cells that cannot be written at all. Analogue of MemTest86+ T1/T2.

Test 3 — Bus stress [turnaround]

Intensive read→write→read transitions with all data bits toggled in every word. Stresses the data bus and turnaround timings; catches bus instability and weak data signals. Analogue of MemTest86+ T3.

Test 4 — Moving Inversions [1s & 0s + random]

Classic moving inversions: fill with 1s/0s patterns followed by bit-by-bit inversion + random patterns. Checks every cell for 0→1 and 1→0 transitions and for neighbor influence. Analogue of MemTest86+ T4/T5.

Test 5 — Moving Inversions 8-bit [pattern]

Walking ones and zeros in 8-bit view: the pattern rotates through every byte and sweeps all 256 combinations (8 bits). Catches failures that depend on neighboring bits within a byte. Analogue of MemTest86+ T6.

Test 6 — Modulo-20 [anti-cache]

A pattern with a 20-address stride, chosen so it cannot be "masked" by the cache (beats cache associativity). Writes and verifies from that stride. Analogue of MemTest86+ T7.

Test 7 — Block move [64 moves]

Block move of 64 memory blocks into each other and back. Stresses the memory bus with bulk copies; catches errors under heavy multi-channel work and row/column failures under load. Analogue of MemTest86+ T8. The verification pass is correctly interrupted when the test is stopped — phantom errors excluded (v2.82).

Test 8 — Moving Inversions 32/64 [shift]

A pattern shifted by one bit per address, with 64 different offsets. Covers all bit-shift combinations in 32/64-bit words. Analogue of MemTest86+ T9.

Test 9 — Bit-Fade / retention [direct]

Fills all memory with a pattern, waits 30 seconds (retention pause) and re-reads. Finds cells losing charge — degradation (retention) failures that other tests miss because they verify right after writing. Analogue of MemTest86+ T10.

Test 10 — Rowhammer [Blacksmith-style]

A simplified Blacksmith approach: intensively hammers aggressor rows, then checks neighboring victim rows. Catches charge leakage between physically adjacent rows under frequent activation — the classic Rowhammer failure. Analogue of MemTest86+ v7 Test 11.

Test 11 — March-C- multi-pattern [direct]

6-phase March-C- with three patterns over physical memory (no cache interference). Covers stuck bits, transition faults and coupling faults between adjacent cells. One of the strongest functional tests.

Test 12 — Checkerboard / Adjacent-Cell [direct]

Checkerboard fill (alternating 0/1) + a "butterfly" phase (flipping neighbor cells). Checks coupling influence of adjacent cells on each other and on the data bus.

Test 13 — Walking Ones/Zeros [exhaustive]

Full exhaustive test: a one "walks" through every bit of every word, then the inversion. Very slow but maximally complete per-bit coverage. Analogue of MemTest86+ T13/Walking.

Test 14 — Cache Evict Storm [CLFLUSH]

Every cache line is force-evicted with CLFLUSH before reading — every read goes physically to DRAM. Loads the memory controller and VRM with a heavy uncached read stream.

Test 15 — VRM Square-Wave [AVX2]

Square-wave load switching on the VRM: 10 Hz cycles of "AVX2 FMA burst" ↔ "idle". Creates sharp current transients; catches memory power instability, voltage droops and related failures.

Test 16 — L3 Stress [L3 resident]

Read-modify-write in a ~1 MB set that fits in L3. A closed loop over the same lines — repeatedly loads specific banks and rows; catches hidden retention/coupling failures in "hot" rows.

Test 17 — Thermal Soak [3 min, AVX2]

3 minutes of continuous AVX2 FMA load + writes on all cores. Heats the memory and IMC to maximum power; catches temperature-dependent failures (appear only on hot memory). Temperature is monitored throughout.

Test 18 — BW Soak [5 min, AVX2]

5 minutes of streaming writes (non-temporal stores, vmovntdq — no cache pollution) followed by verification. Keeps the memory controller at maximum bus/channel bandwidth; catches failures under full bus load.

Test 19 — Stride-sweep BW [probe]

Read bandwidth measurement at strides of 64B / 1KB / 4KB / 64KB. Probes cache associativity and channel/bank interleaving — a performance diagnostic, not just errors: shows whether memory meets its rated characteristics.

Test 20 — Vector PRSG [AVX2]

A pseudo-random 4×64-bit stream (xorshift) on AVX2: fill + forward/reverse verification. High-entropy patterns cover inter-bit dependencies that "orderly" patterns miss.

Test 21 — Rowhammer [TRR-safe]

TRRespass-style: 8 primary aggressor rows with a simple stride + rotation, double activations for DDR5. Bypasses TRR (Target Row Refresh) protection — finds vulnerable rows that "ordinary" Rowhammer 10 misses because of refresh protection.

Test 22 — Bit-Fade Sweep [retention]

Graded degradation sweep: 5/30/120 s pauses (solid one); on detecting a fade — escalation to 5/15/30/60/120 s with two patterns. Produces a CRITICAL/WARNING/OK verdict from the first failure and stable addresses.

Test 23 — CFst [state coupling]

Writes state into an aggressor row of the same bank, then reads the victim row without a reset. Finds coupling faults where the aggressor state affects reading the adjacent row (state-coupling fault).

Test 24 — March SS [22-phase]

22-phase march test: full state-coupling (CFst) + transition fault (TF) coverage. The most complete march algorithm in use.

Run All Tests

Runs the functional tests 1-13 twice, then thermal/load 14-20 four times (shown as x2/x4 in the progress). Stops on ESC. Results are collected into a table with per-test speed, bandwidth and skip reasons (e.g. no AVX2 / no CLFLUSH / isolated slot).

Анализ ошибок и диагностика

RU
  • Живой декод адреса — текущий физический адрес раскладывается в канал/планку/ранг/банк-группу/банк/строку/столбец (формат Intel SA_ADDRESS_DECODE) через восстановленную карту памяти; правая панель рисует планку с подсветкой активного ранга и подсчётом ошибок по микросхемам.
  • Восстановление карты адресов (методика DRAMA) — по таймингу CLFLUSH и латентности пар адресов определяются биты банков, шаг строк, канал/DIMM-интерлив и ранг; каждая функция самопроверяется через same-bank set'ы (неверный кандидат не может пройти). Для DDR4 отдельно выделяются биты банк-группы.
  • Анализ залипших битов — подсчёт ошибок по каждому из 64 битов данных, вывод «залипших» и «плавающих» битов.
  • DIMM Error Map — карта ошибок по планкам и микросхемам (DQ), монотонные счётчики без обрезания; автоизоляция неисправной планки (SMBIOS Type 20) с вердиктом REPLACE / перестановка слотов.
  • Chip diagnosis (DQ map / Raw Card) — для DDR4 каждый бит ошибки переводится в физическую линию DQ через JEDEC nibble-карту (SPD 60-77) с rank mirroring, и в конкретный чип на планке; DQ-карта сверяется с эталоном Raw Card (SPD 130) → OK/MISMATCH. Для DDR3 — стандартная JEDEC-группировка bit/width (в SPD нет DQ-карты).
  • BadRAM export — генерация строк badram=addr,mask / memmap= / pages= для GRUB2, Linux и Windows (bcdedit). Слияние по алгоритму memtest86+ badram.c, ≤20 паттернов, гарантированное покрытие. Rowhammer и кэш-фантомы исключаются.
  • Flaky-errors / cache-phantom — повторная проверка подозрительного адреса через разные пути (WBINVD / CLFLUSH / non-temporal / uncached): если ошибка «плавает» между прогонами — это кэш-фантом, помечается отдельно от настоящих ошибок.
  • Телеметрия платформы — счётчики IMC retry/replay (Intel MCHBAR): +0 clean / предупреждение / VERDICT «marginal DRAM signal»; мощность RAPL / fam15h, температура, MCA/ECC и перезапуски за прогон; сводка в NVRAM для сравнения между загрузками (ошибки, Tmax, BW).
EN

English — error analysis and diagnostics

  • Live address decode — the current physical address is decomposed into channel/DIMM/rank/bank-group/bank/row/column (Intel SA_ADDRESS_DECODE format) via the recovered memory map; the right panel draws the module with the active rank highlighted and per-chip error counts.
  • Address map recovery (DRAMA method) — CLFLUSH timing and address-pair latency are used to derive bank bits, row stride, channel/DIMM interleave and rank; every function self-checks via same-bank sets (a wrong candidate cannot pass). For DDR4 the bank-group bits are derived separately.
  • Stuck-bit analysis — error counts per each of the 64 data bits; "stuck" and "floating" bits are reported.
  • DIMM Error Map — error map per module and chip (DQ), monotonic counters without truncation; auto-isolation of the faulty module (SMBIOS Type 20) with a REPLACE / slot-swap verdict.
  • Chip diagnosis (DQ map / Raw Card) — for DDR4 every failing bit is translated into a physical DQ line via the JEDEC nibble map (SPD 60-77) with rank mirroring, and into a specific chip on the module; the DQ map is verified against the Raw Card reference (SPD 130) → OK/MISMATCH. For DDR3 — standard JEDEC bit/width grouping (no DQ map in SPD).
  • BadRAM export — generates badram=addr,mask / memmap= / pages= lines for GRUB2, Linux and Windows (bcdedit). Merging follows the memtest86+ badram.c algorithm, ≤20 patterns, guaranteed coverage. Rowhammer and cache phantoms are excluded.
  • Flaky errors / cache phantom — the suspect address is re-checked through different paths (WBINVD / CLFLUSH / non-temporal / uncached): if the error "floats" between passes it is a cache phantom and is tagged separately from real errors.
  • Platform telemetry — IMC retry/replay counters (Intel MCHBAR): +0 clean / warning / VERDICT "marginal DRAM signal"; RAPL / fam15h power, temperature, MCA/ECC and restarts per run; a summary goes to NVRAM for cross-boot comparison (errors, Tmax, BW).

Поддерживаемое железо

RU
  • SMBus (SPD) — Intel legacy (B0:D31:F3), Intel PCH (B0:D31:F4), AMD FCH / ATI SBx00 (B0:D20:F0, включая SB6xx–SB9xx, Hudson/Bolton/Promontory). Прямое чтение страницы SPD 0 с фолбэком при блокировке.
  • SPI BIOS — Intel PCH (HWSEQ, MMIO, фиксированные SPIBAR 0xFED01000 / 0xFED1F800), AMD FCH FIFO (SB6xx–Bolton), AMD SPI100 (Yangtze, Promontory, Zen2/3/4).
  • IMC live-config — Intel MCHBAR (Skylake/Coffee Lake и аналоги, включая CAS-тайминги), AMD Zen SMN/UMC; счётчики IMC retry/replay на Intel.
  • Мониторинг — мощность RAPL (Intel/AMD), fam15h, температура, MCA/ECC, определение перезагрузок.
  • SIMD — AVX2 для нагрузочных тестов 15/17/18/20 (при отсутствии — тесты помечаются «skip: no AVX2», остальные работают).
  • Архитектура — только X64 (UEFI).
На части серверных плат BIOS блокирует SPD-диапазон после инициализации памяти — тогда чтение вернёт 0xFF (планка будет помечена как empty/blocked), но SMBIOS-данные всё равно попадут в отчёт.
EN

English — supported hardware

  • SMBus (SPD) — Intel legacy (B0:D31:F3), Intel PCH (B0:D31:F4), AMD FCH / ATI SBx00 (B0:D20:F0, including SB6xx-SB9xx, Hudson/Bolton/Promontory). Direct SPD page-0 read with a fallback when locked.
  • SPI BIOS — Intel PCH (HWSEQ, MMIO, fixed SPIBAR 0xFED01000 / 0xFED1F800), AMD FCH FIFO (SB6xx-Bolton), AMD SPI100 (Yangtze, Promontory, Zen2/3/4).
  • IMC live-config — Intel MCHBAR (Skylake/Coffee Lake and similar, including CAS timings), AMD Zen SMN/UMC; IMC retry/replay counters on Intel.
  • Monitoring — RAPL power (Intel/AMD), fam15h, temperature, MCA/ECC, restart detection.
  • SIMD — AVX2 for load tests 15/17/18/20 (when absent those tests are marked "skip: no AVX2"; the rest still run).
  • Architecture — X64 (UEFI) only.
On some server boards the BIOS locks the SPD range after memory init — the read then returns 0xFF (the module is marked empty/blocked), but SMBIOS data still reaches the report.
